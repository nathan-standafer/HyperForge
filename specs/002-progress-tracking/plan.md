# Implementation Plan: Progress Tracking & Charts

**Branch**: `002-progress-tracking` | **Date**: 2026-04-15 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `/specs/002-progress-tracking/spec.md`

## Summary

Build read-only progress visualizations on top of the workout-logging
data already persisted in local SQLite. Users open an exercise to see
time-series charts of top weight, estimated 1RM (Epley), and total
volume; a dashboard surfaces recent workout count, volume, weekly
streak, and new PRs; a PR history view shows best-ever weights per
standard rep range. All computations run locally against existing
tables — no schema changes, no network dependency. Charts render via
a single, lightweight charting dependency (`victory-native`) chosen
for Expo compatibility and small footprint.

## Technical Context

**Language/Version**: TypeScript 5.x on Node.js 20+
**Primary Dependencies**: Expo SDK 52+, expo-sqlite (existing),
expo-router (existing), victory-native (new, charting),
react-native-svg (victory-native peer dep)
**Storage**: Read-only access to existing SQLite tables (exercises,
sessions, sets). No new tables required for v1.
**Testing**: Jest + React Native Testing Library (existing)
**Target Platform**: iOS 15+ and Android 10+ (mobile-first)
**Project Type**: mobile-app
**Performance Goals**: Progress view open <2s, filter change <500ms,
60 fps chart interaction, one year of data renders smoothly
**Constraints**: Offline-only (no network), derive all metrics from
local data, current-unit display via existing preference
**Scale/Scope**: Single user, ~3 new screens (dashboard, exercise
progress, PR history), ~5 new services/components
